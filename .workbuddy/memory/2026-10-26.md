## 一键启动脚本：start.bat / start.sh（2026-10-26 收尾）

**功能**：检测 Node.js → .env 缺失时由 .env.example 生成 → 校验 DEEPSEEK_API_KEY 是否填写（空 / sk-YOUR_KEY_HERE 均警告）→ 打印品牌横幅与访问地址 → 前台 `node server.js`（Ctrl+C 停）。端口优先级：第 1 参数 > 环境变量 PORT > 3000；SKIP_BROWSER=1 关闭自动开浏览器。

**Windows 关键坑（重要，跨项目通用）**：
1. **bat 必须 GBK(cp936) + CRLF**。曾用 UTF-8 + `chcp 65001`：cmd 在切代码页前已按 GBK 读取首块，多字节错位把 `REM` 行撕裂成伪命令，报 "'作者：岳泽霖' is not recognized"。解法 = 文件存 GBK + 开头 `chcp 936`；Node 的输出是 UTF-8（WriteConsoleW），与 bat 的 GBK 输出在各自通道都正确，重定向混合时才看到乱码，真实 cmd 窗口正常。
2. **REM 注释里不能写 `|` 和 `>`**（cmd 会对 REM 行做管道/重定向解析），曾导致 "| was unexpected at this time"。
3. 特殊字符需转义：`^( ... ^)`、`^>=`、`2^>nul`。
4. 验证手段：`head -N start.bat > tmp` 二分定位；输出重定向到文件后用 Python 按 GBK 解码验证中文正确性（Bash 终端本身按 UTF-8 渲染 GBK 会显示乱码，不代表脚本有问题）。

**Git Bash 下的检测陷阱**：`grep -c $'\r'` 不可靠（会误报全部命中），判断换行符/编码一律用 Python 读 bytes 统计 `\r\n` / `\n` / BOM。

**sh**：`bash -n` + 隔离副本（cp 项目文件到临时目录）测试三分支（无 .env / 已填 Key / 占位 Key）全通过；注意 MSYS /tmp 与 Windows temp 路径不一致，测试应在同盘项目目录或用 `$(dirname "$0")` 语义。

**另外**：`.env.example` 占位符由 `sk-在这里填入你的Key`（含中文）改为 `sk-YOUR_KEY_HERE`（纯 ASCII），脚本判断零编码风险。
